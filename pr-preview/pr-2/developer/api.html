API reference

Every surface an integration or automation can build on, generated from the shipping code. Labels and descriptions are the same strings Home Assistant shows in its own dialogs, so this page and the UI never disagree.

New to this? Start with the integration guide, which walks through calling a service and reacting to its event.

Surface coverage​

Every kind of integration surface Home Assistant offers, and the status of each one here. The rows that say not applicable or deferred are the useful ones: a list of what exists cannot tell you what is missing.

SurfaceStatusNotes
Actions (services)PublishedEach operation that changes or exports Car Keeper data is a car_keeper.* service.
Bus eventsPublishedEach state change fires a car_keeper_<noun>_<verb> event with a payload from a pure builder.
Device triggersNot applicableThe bus events and the entities give the triggers of an automation.
Device conditionsNot applicableThe sensors of each car give the state that a condition reads.
Device actionsNot applicableThe services cover each operation and take a car id directly.
Entity platformsNot applicableCar Keeper has no entity platform yet.
Entity attributesNot applicableCar Keeper has no entity yet.
Config entry optionsPublishedThe distance unit of a new car.
Config flowPublishedA single-instance setup flow with a distance unit field, and an options flow that changes it.
Websocket commandsInternalThe tab and the cards read the state and call the twin of each service.
HTTP routesInternalA static path for the bundles.
DiagnosticsPublishedThe config entry gives a diagnostics download, with the VIN and the plate redacted.
Reauth / reconfigure flowsNot applicableCar Keeper has no credential. The storage is local.
Repairs / issue registryPublishedAn issue shows when Home Keeper is missing, not set up or too old for the tab.
DiscoveryNot applicableNo device or service on the network is a car record.
Home Keeper panel tabInternalThe admin UI is a tab in the Home Keeper panel, registered through the Python API of Home Keeper.

Actions​

Every operation that changes or exports data is a Home Assistant action, so automations, scripts, voice assistants and other integrations all reach it the same way. Guard each call with hass.services.has_service("car_keeper", "<action>") so your integration still works when this one is not installed.

car_keeper.set_settings​

Set settings

Changes the settings of Car Keeper. Admin only.

Admin only · Can return a response

FieldLabelSelectorDescription
unitDistance unitselect (km, mi)The unit of a new car: km or mi.

Events​

The integration fires a bus event for every observable state change. Names follow car_keeper_<noun>_<verb>. For when each one fires in context, and worked automations, see the events guide.

EventFires whenPayloadAdds
car_keeper_settings_updatedA setting changed.settings

The integration also listens for events it does not own:

EventReaction
home_keeper_register_companionsCar Keeper registers as a companion again.

Payloads​

Events sharing a payload shape are interchangeable in one automation template. Per-event additions from the table above merge onto these.

Settings payload​

Carried by car_keeper_settings_updated.

FieldTypeNotes
changed_fieldslist[str]The settings that changed.
originstr | NoneThe origin marker of the caller.

Entities​

The integration's state is readable as ordinary entities, so most automations never need to call an action to find something out.

Config entry options​

The options of the config entry. The ones marked Configure dialog are on the options form of the integration. The set_settings action writes the currency too.

OptionLabelWhereNotes
unitDistance unitConfigure dialogThe unit of a new car. A car that you added keeps its unit.

Errors​

A rejected action raises a localized Home Assistant error. The key is stable; the message shown is in the user's language.

KeyEnglish message
not_loadedCar Keeper is not loaded. Try again after it starts.
